## 0. Executive summary

Makina is a multi-agent software-factory orchestrator in Rust with a ratatui
TUI as its entry point. You point it at a structured-Markdown task list; a
**Planner** turns it into a dependency-aware task graph; a **Supervisor** drives
each task through a **develop → gate → review → merge** loop using an external
ACP agent CLI (e.g. `gemini --acp`), isolating every task in its own git worktree
and squash-merging approved work into your base branch.

This is a genuinely well-engineered MVP. The architecture bets from plan 0001 —
star-topology kameo actors, an explicit task FSM, worktree-per-task isolation,
the swappable `AgentBackend` trait, the `NoopBackend`-first testing strategy, and
the thin-shell TUI over `Arc<dyn Api>` — all held up under a real agent and under
234 commits of subsequent hardening. The layering is clean, the test density is
high (~872 tests, every one hermetic), and the concurrency model is correctly
reasoned about (graph lock never held across an await, merge lock separate from
graph lock, permit-per-driver lifetime).

The most important findings are **not** architectural correctness issues. They
are:

1. **The README is stale on the highest-impact UX issue.** It still says Makina
   "does not yet answer `session/request_permission`" and recommends `--yolo`.
   The ACP crate **does** answer it — via a pluggable `PermissionPolicy` with an
   auto-allow-inside-worktree default and a full audit ledger. This is the
   project's headline governance feature and the docs hide it.
2. **A cluster of small, high-leverage UX bugs** in the TUI that each undercut
   the polish plan 0036/0037 aimed for: inactive tab labels are unreadable
   (`bg(Dim).fg(Dim)`), the wall-clock countdown is hardcoded, there is no
   help/keymap screen, the error pane isn't scrollable, and the provider editor
   can't actually edit.
3. **The VISION's "tracked artifact" principle is now met at runtime** (plan
   0029/0030 landed atomic `.makina/tasks/{slug}.json` persistence + crash
   recovery), closing the largest gap the trial findings flagged. Good.
4. **Two deferred-but-real protocol risks** in the ACP client: no turn timeout
   (a wedged agent hangs the orchestrator), and `session/cancel` is never sent
   (teardown-by-SIGKILL is the only stop).

None of these block using Makina today. (1) and (2) are the immediate
follow-ups I'd schedule; (3) is done; (4) is the next protocol-hardening pass.

## 1. What this is

A Rust workspace (edition 2024, built with 1.94) of three crates:

| Crate | Role | LOC (src) |
|-------|------|-----------|
| `makina-core` | Orchestration engine: kameo actors, task FSM, worktrees, gates, squash-merge, config, agent-backend trait, `Api` surface | ~30,600 |
| `makina-acp` | The ACP `AgentBackend`: spawns the agent CLI, JSON-RPC over stdio, permission policy, audit, process-group reaper | ~4,900 |
| `makina` | The ratatui TUI binary and entry point; presentation-only over `Arc<dyn Api>` | ~7,200 (prod) + ~22,000 tests |

The TUI is the only entry point: `cargo run -p makina`. There is no CLI/REST
surface; everything happens in the terminal.

The arc of work is visible in `docs/plans/`: 48 plan folders, 0001 (Initial MVP)
through 0037 (Audit & Fix Ayu Theme Distinctness). The trial findings
(`docs/trial/trial-findings.md`) document the first real-agent end-to-end run
and the gaps it exposed; plans 0002–0037 are the response to those findings plus
TUI hardening. Source-available under Elastic License 2.0 (not OSI open source).

## 2. Architecture review

### 2.1 The layering is sound and enforced

The stated boundary — "all logic in `makina-core`, the TUI consumes only the
`api` query/command/event surface, agents are external processes behind the
swappable `AgentBackend` trait" — is actually respected in the code:

- `makina` imports `makina_core::api::{Api, Command, Event, ...}` and
  `makina_core::orchestrator::{CoreApi, PlanEntry}`. It never imports actor
  internals, the FSM, or the backend trait. A `no_frame_bypass.rs` structural
  test even pins that `main.rs` has no stray `print!`/`eprintln!` that would
  corrupt the live ratatui frame.
- `makina-acp` implements `makina_core::backend::{AgentBackend, AgentSession}`
  and is the only crate that knows the ACP wire format. Swapping it for a
  different protocol is a constructor change in `main.rs`.
- The `Api` trait (`makina-core/src/api.rs:967`) is `Send + Sync`, `&self`
  methods, object-safe — proven by the TUI holding it as `Arc<dyn Api>` and by
  a `StubApi` test.

This is the "maximalist core, thin shell" principle from the VISION, and it
holds.

### 2.2 The task FSM is pure, explicit, and exhaustive

`state_machine.rs` is a pure `(state, event) → state` function with no I/O, no
actor coupling, no caps. The Supervisor calls it under the graph lock. Seven
states (`New/Ready/InProgress/InReview/Done/Failed/Skipped`), 14 events, 21
legal transitions. An exhaustive 7×14 Cartesian-product test
(`state_machine.rs:417-459`) pins the table: 21 legal / 77 illegal / 98 total.

The two plan-0017 reset edges (`Failed→New` via `RetryRequested`,
`Skipped→New` via `DependencyReset`) are the only non-obvious additions, and
they're correctly tested.

**Minor doc rot** (not a code defect): the module doc and inline test comments
still say "19 legal / 65 illegal / 84 pairs (7×12)" — the text wasn't updated
when `RetryRequested`/`DependencyReset` were added. The code and the test
assertions agree on 21/77/98. (`state_machine.rs:325-336`, `state_machine.rs:412-415`.)

### 2.3 The Supervisor's concurrency model is correctly reasoned about

This is the part I most expected to find bugs in, and didn't. The scheduler
(`supervisor.rs:1170-1496`):

- **Permit-per-driver lifetime.** `tokio::sync::Semaphore(concurrency)`; each
  driver `acquire_owned()`s a permit and releases it on completion/error/panic/
  timeout. A crashed driver never leaks a slot.
- **Graph lock never held across an `.await`.** `Arc<tokio::sync::Mutex<TaskGraph>>`;
  every mutation is acquire → mutate → drop → then await. The helpers
  `apply_event_locked`/`task_mut_locked`/etc. take a borrowed guard while the
  caller holds it. This is disciplined.
- **Lock ordering avoids deadlock.** (1) semaphore permit (driver lifetime),
  (2) graph lock (tight, non-awaiting), (3) merge lock (taken only for the
  merge; graph lock NOT held while awaiting it). No cycle.
- **Continue-on-failure.** A task-level `Failed` does NOT stop launching
  independent ready tasks; only a genuine driver panic sets `fatal_error` and
  halts. A `Done` task may unlock dependents → the fill/drain loop re-fills.
- **Wall-clock cap.** Each driver future is wrapped in
  `tokio::time::timeout(wall_clock, ...)`. On timeout the future is cancelled,
  its `DriverGuard` tears down the worktree + spokes, the permit is released,
  and `WallClockCapReached → Failed` is applied under the graph lock.
- **Pause/Cancel.** Pause stops launching (in-flight finish); Cancel calls
  `join_set.abort_all()` and each aborted driver's `DriverGuard` still tears
  down (no leak).

The `DriverGuard` (`supervisor.rs:1556-1598`) is RAII: kills spokes in `Drop`
(synchronous, idempotent), best-effort `tokio::spawn`s worktree removal (can't
`.await` in `Drop`). The "best-effort" here is the one place a worktree could
theoretically be orphaned if the spawned removal task itself fails to schedule;
in practice the reaper + the next run's `prune` + the reclaim-on-conflict path
in `WorktreeManager::create` cover it.

### 2.4 Worktree & merge safety is the strongest part

- **The prune↔add race is fixed** (`worktree.rs:151-169`). `WorktreeManager`
  carries an `op_lock: Arc<Mutex<()>>` serializing `create`/`remove`'s git
  metadata ops across all clones (shared via `Arc`, so one `new()` = one
  process-wide lock per repo). The guard is held only around fast git metadata
  ops, never across dev/review work, so it doesn't serialize tasks themselves.
  This was a real bug (`8db4c8a`) and the fix is correctly scoped.
- **Reclaim-on-conflict** (`worktree.rs:254-267`): if a worktree path or branch
  already exists (stale slot from a crashed prior run), it warns, removes the
  stale slot, and recreates fresh off the fork point. This is Option A (reset,
  not resume) — correct, because the prior attempt was never merged.
- **The base-branch-never-broken invariant.** `SquashMerger::restore_base_branch`
  (`merge.rs:420-441`) runs `git merge --abort` (best-effort, ignored) →
  `git reset --hard HEAD` (MUST succeed) → `git clean -fd` (MUST succeed). The
  last two are load-bearing; their failure is a hard `MergeError`. On conflict
  the merger restores the base branch BEFORE returning `MergeOutcome::Conflict`,
  so `develop` is never left in a broken merge state. This is the property the
  trial findings explicitly verified ("develop was never corrupted in any test")
  and it holds.
- **`--allow-empty` everywhere** (`merge.rs:29-36`, `developer.rs:432-437`):
  every approved task lands a commit on the base branch even if the agent made
  no file changes, giving a uniform audit trail.
- **Idempotent teardown.** `remove_inner` treats "not found" as success for both
  `git worktree remove --force` and `git branch -D` (via `is_not_found_stderr`).
  Re-running cleanup on an already-cleaned slot is a no-op.
- **Plan branch** (`worktree.rs:388-408`): `plan/{slug}` is created off
  `base_branch` and tasks squash-merge into it; the final merge
  (`final_squash`/`final_merge_commit`, `merge.rs:300-396`) lands `plan/{slug}`
  onto `base_branch`. Configurable via `FinalMerge::Squash` (default) /
  `MergeCommit` / `Manual` (`config.rs:313-337`).

### 2.5 Gates & governance: the spec matches the code

`docs/spec/deterministic-governance.md` is normative — it describes implemented
behaviour, and I verified every symbol it cites exists and behaves as
described:

- Gates are exit-code-zero shell commands via `sh -c` (or `docker run` when
  `gate.image` is set), run in the worktree, **after** the Developer turn and
  **before** the Reviewer. `GateRunner::run_gates` stops at the first failing
  gate; the Supervisor re-runs all gates from the top on the next iteration.
- **Discovered gates** (plan 0025/0026) merge into the same `[[gates]]` array
  with `source = "discovered"`; execution ignores `source`. Discovery is
  model-driven; execution is deterministic. The written `config.toml` is the
  single auditable record.
- **Loop-back + shared cap.** Gate failure → `GateFailed` (InProgress self-loop)
  → `gate_iterations += 1` → feedback string to the Developer → re-run all
  gates. Cap (`caps.gate_iterations`, default 5) → `GateCapReached → Failed`
  with `FailureKind::GateCap` reason.
- **Output truncation** to the last 16 KiB (`gate.rs:64`) — correct bias toward
  failure summaries that appear at the tail.

The trial's clean first-pass (0 gate iterations, 0 review iterations) confirms
the loop works against a real agent, not just in unit tests.

### 2.6 The ACP backend is well-factored, with two protocol gaps

`makina-acp` has a clean three-layer split:

- `transport.rs` — generic newline-delimited JSON-RPC over any
  `AsyncRead + AsyncWrite`. Testable with `tokio::io::duplex`. This is where the
  testing strategy hinges, and it's sound.
- `client.rs` — `AcpClient`: spawn → `initialize` → `session/new` → prompt →
  shutdown. Owns the subprocess lifecycle (`kill_on_drop(true)` + Unix
  `process_group(0)` so the agent is its own group leader).
- `backend.rs` — maps `AcpClient` onto `makina_core::backend::{AgentBackend,
  AgentSession}`. The borrowing→owned stream bridge (move client into a
  `tokio::spawn` worker, return it over a oneshot) is the cleverest piece and
  is correctly reasoned about: the `AgentSession::prompt` contract requires an
  owned `'static` `ResponseStream`, but `AcpClient::prompt` borrows
  `&mut transport`; the worker drains the borrowing stream and forwards mapped
  events over an `mpsc::channel(64)`, returning `Box::pin(ReceiverStream)`.

**The permission flow is fully implemented** — contradicting the README. The
transport's `route_message` Request arm (`transport.rs:447-561`) handles
`session/request_permission`: deserialize params → build
`PermissionRequestContext` → invoke `policy.decide()` (synchronous) → reply
`PermissionOutcome::Selected { option_id }` (allow) or `Cancelled` (deny) →
emit an `AuditEntry` to the injected `AuditSink`. Other inbound requests get
`-32601 method not found` so the peer never hangs.

`WorktreePolicy` (`permission.rs:81-136`) is the MVP default: auto-allow
(selecting the first `AllowOnce` option) iff `ctx.working_dir == self.worktree`;
deny outside. Every auto-allow is audited. This eliminates the need for
`--yolo` for the common case of an agent working inside its assigned worktree.

**Two protocol gaps worth flagging:**

1. **No turn timeout.** `Transport::send_request` awaits the oneshot
   indefinitely (only woken by reader termination). A wedged agent that holds
   stdout open but never replies hangs the orchestrator forever. The real-CLI
   tests bound this with an external 120s `tokio::time::timeout`, but production
   `AcpClient`/`AcpSession` has no internal turn timeout. The Supervisor's
   per-task `wall_clock_secs` cap is the only backstop, and it's minutes-scale.
   **This is the most significant protocol-level risk.** (Plan 0021 / 0015
   added an idle-output watchdog at the Developer/Reviewer actor level
   (`developer.rs:290-309`), which mitigates the silent-stall case — but the
   transport itself has no request-level timeout.)
2. **`session/cancel` is never sent.** `METHOD_SESSION_CANCEL` and `CancelParams`
   are declared (`protocol.rs:54`) but nothing in `client.rs`/`backend.rs` ever
   calls it. Cancellation is teardown via `shutdown`/`terminate`
   (SIGTERM → 200ms grace → SIGKILL). The lib.rs doc-table marking
   `session/cancel` as "(available)" is misleading — it's available at the
   transport seam but not wired into the client API. There's no polite way to
   cancel an in-flight turn while keeping the session alive.

**Smaller ACP issues:**
- `usage` is hard-coded to `None` (`backend.rs:604-611`); the protocol parses
  `PromptResult.usage` but `AcpResponseChunk::TurnComplete(StopReason)` carries
  only the reason, so token counts never light up in the TUI's per-role metrics.
- `stop_reason` is dropped at the trait boundary (`backend.rs:601-602`); a
  `Refusal` is indistinguishable from `EndTurn` to the orchestrator.
- `WorktreePolicy` does no path validation inside `tool_call`
  (`permission.rs:77-80`) — it keys off the session `working_dir`, not the
  actual tool-call target paths. Sandboxed enforcement is future work.
- `run_id`/`task_id` in audit entries are placeholders (`transport.rs:503-504`:
  `run_id: "acp-transport"`, `task_id: None`) — the transport has no run/task
  context, so audit entries can't be correlated to a specific run without
  threading that context through `Transport::new`.
- Permission response is fire-and-forget (`let _ =` at `transport.rs:483`); if
  the write fails the audit entry still records `Allow` though the agent never
  received it.
- Forward-compat is good: pervasive `#[serde(other)]` on enums and
  `#[serde(flatten)] extra: HashMap<String, Value>` on structs, explicitly
  tested with captured gemini payloads preserving unknown fields.

### 2.7 Persistence & crash recovery: the big trial gap is closed

The trial findings (`docs/trial/trial-findings.md` §2) flagged
"`.tasks/{slug}.json` persistence never written — task graph is in-memory only"
as the second-highest-priority gap. **This is now fixed.**

- `persist.rs` does atomic graph persistence: write to temp
  `.{slug}.json.tmp.{pid}.{seq}` (same dir → rename is same-filesystem) →
  `tokio::fs::rename` atomically onto `{slug}.json`. Temp naming uses a
  process-global `AtomicU64` seq to avoid collisions across concurrent
  processes AND concurrent calls within a process.
- `recover_for_resume` (`persist.rs:265-278`) is pure, synchronous post-load
  repair: `InProgress`/`InReview` → `Ready`; preserves
  `gate_iterations`/`review_iterations`/`started_at`/`finished_at`; deliberately
  bypasses the FSM (crash-resume is not a normal lifecycle event).
- `run_metadata.rs` writes `run.json` per finalized run and
  `load_disk_run_views` surfaces historical runs after process restart — the
  seam `CoreApi::runs` uses to show past runs in the sidebar.
- A `.gitignore` invariant test (`persist.rs:545-600`) asserts `.makina/` is
  not ignored and `/runs/`+`/worktrees/` rules are absent (runtime state is
  off-repo now, under `~/.makina/projects/{project_ns}/`).

**One rough edge:** `run.json` itself is written best-effort with a single
  write-once (`run_metadata.rs:173-185`), no atomic temp/rename — unlike
  `persist_graph`. A crash mid-write could leave a truncated `run.json`. Low
  impact (it's a historical record, not the source of truth) but inconsistent
  with the graph persistence discipline.

**Stale doc comment** (`run_metadata.rs:69-71`): claims
  `WorktreeManager::worktree_path` "still returns the pre-relocation path" —
  it doesn't; it delegates to `paths::worktree` which returns the relocated
  off-repo path. The comment predates plan 0029.

### 2.8 Config layering is solid

Two-layer TOML (`~/.makina/config.toml` global + `.makina/config.toml` project,
project wins) with back-compat synthesis for the legacy `[backend]` section
(`config.rs:714-754`: if `providers` is empty but `[backend]` exists, synthesize
a `"default"` provider). Validation is thorough
(`config.rs:804-928`: provider commands non-empty, unique provider names, role
assignments reference declared providers, caps ≥ 1, concurrency ≥ 1, gate
name/command non-empty, base_branch non-empty). The planner's `DirectApi`
mechanism returns `MechanismNotSupported` rather than panicking
(`config.rs:250-258`) — honest about what's implemented.

### 2.9 Architectural smells (minor, non-blocking)

- **Domain→view coupling.** `Task::failure_reason` is typed
  `Option<crate::api::FailureReason>` (`task.rs:181`) — the domain `Task`
  references the view-layer `api` module. The `api` doc
  (`api.rs:142-161`) says "view mirrors domain, no back-arrow", so this is a
  small contradiction. It exists because the Supervisor stores the reason at
  the failure site and the orchestrator carries it through to `TaskView`. Mild.
- **Developer/Reviewer stream-drain duplication.** The stream-drain loop in
  `reviewer.rs:259-386` is near-identical to `developer.rs:289-417` (~130 lines
  of duplicated idle-watchdog + side-channel forwarding + `RoleTurnMetrics`
  emission). A shared `drain_agent_turn` helper would cut this. Not a bug.
- **`combine_output` defined twice** — identical bodies in `gate.rs:241` and
  `merge.rs:482`, each with its own unit test. A shared helper would eliminate
  this.
- **Dead/stale `#[allow(dead_code)]`.** Several items carry stale allows for
  symbols that ARE used: `is_plan_convention_dir` (`orchestrator.rs:190`),
  `format_tasks_section` (`ui.rs:2170`), `accordion_section_order`
  (`app.rs:1771`), `PlaceholderApi::empty` (`placeholder.rs:72`). Cosmetic.
- **Forward-referenced stub events.** `AppEvent::RetryFocusedTask` and
  `AppEvent::DiscoverProject` (`app.rs:898-902`) emit "not yet available (plan
  0017/0025)" status messages, but the real `RetryFocused`/`DiscoverProject`
  paths are fully implemented (`event.rs:346, 414`). The stubs are unreachable
  (the palette wires the names to the real events, `app.rs:482-487`) but kept
  for match exhaustiveness. Confusing for a reader.
- **`SettingsCommit` validation duplicated** in both `App::update`
  (`app.rs:2856`, ~300 lines) and `event::commit_settings` (`event.rs:613`).
  Both must stay in sync — maintenance hazard.

## 3. UX review

The TUI is the only entry point, so UX is not a sideshow. The architecture is
excellent (Elm-like pure `update` + pure `render` + a single `resolve_io` IO
boundary, all unit-testable), but there's a cluster of small polish bugs and
discoverability gaps that together undercut the sheen plans 0033–0037 aimed for.

### 3.1 UX strengths (genuine)

- **Elm architecture, fully realized.** `App::update(AppEvent) -> bool` is pure
  synchronous no-IO; `ui::render(&App, &mut Frame)` is pure no-mutation; the
  async event loop (`event::run`) merges four sources via biased
  `tokio::select!` (terminal input, background IO, api subscription,
  tracing→TUI log channel, 250ms tick). `resolve_io` is the only place the TUI
  touches the filesystem or the async api. This is textbook and it pays off in
  testability (~440 test functions in the TUI crate alone).
- **Off-render-loop IO.** Plan discovery, dir reads, and `execute(OpenRun)` are
  `spawn_blocking`/`spawn`ed; the UI stays responsive with a busy spinner.
  Plan auto-discovery runs on startup with a spinner and no popup if no
  `docs/plans/` exist (`fallback_to_browser=false`).
- **Bounded buffers everywhere.** Exchange logs cap 100, error messages cap 50,
  writer cache cap 256 (LRU), TUI log channel cap 256 (drop-on-full, WARN/ERROR
  only). No unbounded memory growth.
- **Mouse + keyboard parity.** Tabs, sidebar rows, accordion headers are all
  clickable and mirror Enter; scroll wheel routes by cursor position
  (plan 0033); in-app mouse text selection with OSC 52 copy works over SSH
  (plan 0035). This re-implements terminal selection because mouse capture
  disables the terminal's own — well-reasoned (`selection.rs:1-39`).
- **Per-panel scrollbars + auto-follow.** Each scrollable panel has its own
  offset and a `Scrollbar`; the exchange pane auto-follows with manual-override
  re-engagement at the bottom.
- **Streaming-safe Markdown.** `markup::render_markdown` is fuzz-tested against
  every char-boundary prefix (`partial_mid_stream_string_does_not_panic`,
  `streamed_prefixes_never_panic`) — no panics on partial agent chunks.
- **Strong no-orphan guarantees.** Panic hook, signal reaper, and
  clean/error teardown all drain the agent process-group registry (`exit.rs`,
  `tui.rs:197-208`, `reaper.rs`). A Ctrl-C or panic doesn't leave agent
  grandchildren alive.
- **Theme system.** Semantic roles (12 `ThemeRole`s + 16 ANSI entries), not raw
  colours; truecolor `Color::Rgb` pinned; runtime switching via command palette
  persisted to `.makina/config.toml`; a distinctness regression test
  (`theme.rs:245`) enforces ≥40 RGB distance between FocusBg and SelectionBg
  across all built-in themes. Plan 0037 closed the Ayu Light gap (FocusBg
  repainted to `#A0BCE6`, ~70 units from SelectionBg).
- **Context-sensitive retry** (`r`) — single key handles failed-task retry,
  failed-run retry, or pending-run reinterpret depending on focus.
- **Doctor + scaffold** (`?`) — health check with a `[w]` write-starter-config
  action for first-run users.

### 3.2 UX bugs & polish gaps (actionable)

These are the items I'd schedule next. Each is small and high-leverage.

#### B1. Inactive tab labels are unreadable — **likely bug**

`render_tab_bar` (`ui.rs:936-938`) styles inactive tabs as
`Style::default().bg(Dim).fg(Dim)` — the same colour for foreground and
background. In Ayu Dark that's `#5A6378` text on a `#5A6378` background: the
tab label is invisible against its own chip. Active tabs are fine
(`Accent` bg + `Background` fg + bold). This is the most visible polish defect
in the current build — open multiple tabs and the inactive ones vanish.
**Fix:** use `Background` (or a muted `Foreground`) for the inactive fg, keep
`Dim` for the bg, or invert (`Dim` fg on `Background` bg with a `Dim` divider).

#### B2. `wall_clock_secs_config` is hardcoded to 600, never synced — **bug**

`App` initialises `wall_clock_secs_config: 600` (`app.rs:1625`) "as a reasonable
default" and it is **never updated** from `caps.wall_clock_secs` at startup or
from any event. The wall-clock countdown/indicator in the exchange pane
therefore uses 600s regardless of what the user configured. If the user set
`wall_clock_secs = 1200` in `.makina/config.toml`, the TUI shows a wrong
deadline. (The actual cap the Supervisor enforces is correct; only the TUI's
displayed countdown is wrong.) **Fix:** seed `wall_clock_secs_config` from the
loaded config's `caps.wall_clock_secs` when a run is opened, like
`idle_secs_config` is seeded from `TaskIdle` events.

#### B3. No help / keymap screen — **discoverability gap**

`?` opens Doctor, not a keymap. The only key discoverability is the status-bar
legend (`ui.rs:807`) — a single dense line that **clips on narrow terminals**
(`ui.rs:795-798`), silently dropping the trailer (which includes the focus label
and last-event hint). On a narrow window many keys are simply invisible. There's
no `h`/`F1`/`?`-second-mode help overlay. **Fix:** add a full-screen help
overlay (keymap grouped by category) bound to `?` (and move Doctor to `!` or a
palette entry), or at minimum make the status bar wrap/scroll instead of clip.

#### B4. Error pane is not scrollable — **gap**

`render_error_pane` (`ui.rs:2208`) auto-scrolls to the newest
(`ui.rs:2250-2257`) but there's no `ScrollablePanel::ErrorPane` and no key to
scroll within it. A long error history can't be inspected upward; older errors
are gone once they scroll off. Given the pane is the primary diagnostic surface
for agent/gate failures, this is a real gap. **Fix:** add `ErrorPane` to the
scroll-routing map and let the mouse wheel + `↑/↓` scroll it when focused, or at
least allow `PgUp/PgDn` when the pane is open.

#### B5. Overloaded `s`/`a`/`t`/`z` are silent no-ops outside plan tabs — **gap**

`s`/`a`/`t`/`z` toggle accordion sections **only** when a plan tab is active and
the main pane is focused; otherwise `s`→StartRun and `a`/`t`/`z` are silent
no-ops with no feedback (`event.rs:1369-1396`). A user on a non-plan tab
pressing `a` gets nothing and no message. The accordion footer help
(`ui.rs:2035`) only appears *inside* a plan tab, so the keys are undiscoverable
elsewhere. **Fix:** either emit a transient "not available here" status message
on the no-op, or make the keys consistent (e.g. always `s` = start, and use
`1`/`2`/`3`/`4` for accordion sections).

#### B6. Provider editor cannot edit — **overpromises**

The provider editor modal (`event.rs:1300-1309`, `app.rs:2422-2437`) is titled
"Configure Providers & Roles" but `ProviderEditorUp`/`Down` only move a
`selection_index`; there's **no key to actually edit** a provider or role
assignment (no Enter-to-edit, no field editing). The only action is Enter =
commit, which writes the unchanged config back. It's effectively a read-only
viewer. **Fix:** either rename to "View Providers & Roles" or implement the
edit path (add/remove provider, reassign role).

#### B7. Sidebar is fixed 30%, not resizable; no min-size guard — **small-terminal gap**

`ui.rs:90` splits the body 30%/70% with no user control. On a 40-col terminal
the sidebar is 12 cols — unusable for run labels like
`makina/0034-test-plan`. There's no minimum-size guard: a 20×5 terminal will
render overlapping/collapsed panes with no graceful "terminal too small" message.
**Fix:** make the sidebar width user-adjustable (e.g. `Shift+←/→` or a drag
handle), and add a min-size fallback screen.

#### B8. `Theme::get` panics on a missing role — **robustness gap**

`Theme::get` (`theme.rs:48-53`) panics if a role is missing from the map. Today
all three built-in themes define every role (guarded by
`themes_define_every_role_and_ansi_entry`), so this is latent. But the
architecture invites custom themes (semantic roles, persisted name in config),
and a half-built custom theme would crash the app at render time rather than
degrade. **Fix:** return a sensible default (e.g. `Foreground` or
`Color::Reset`) on missing role, and log a warning.

#### B9. Markdown re-parsed every frame — **perf risk**

`render_markdown` (`markup.rs:76`) re-parses the entire body every frame for
plan accordions (`ui.rs:1047-1054`) and streaming responses
(`ui.rs:2481-2486`). For large plans or long streaming responses this is O(n)
per tick (250ms) plus per exchange event. No caching/memoization. A big plan
body re-parses pulldown-cmark continuously. **Fix:** cache parsed lines keyed
by `(text_hash, width)` in `App`, invalidate on text/width change.

#### B10. `render_provider_warning` shows only the first missing provider

`ui.rs:2288` shows only the first missing provider in the banner. If multiple
providers are missing, the others are invisible (only `?` Doctor shows all).
Minor, but a user with two misconfigured providers sees one warning, fixes it,
then sees the second appear — confusing. **Fix:** show a count ("2 providers
missing — see Doctor") or cycle.

### 3.3 Accessibility & contrast

- **Status badges are good** — they combine a glyph (`[▶]`, `[✓]`, `[✗]`) AND
  colour, so they're legible without colour.
- **The error badge** relies on a Warn-coloured background to signal unseen
  errors (`ui.rs:779-786`) — colour-only for the "unseen" signal. A glyph
  (e.g. `●`) would make it robust.
- **Ayu Light `Dim #828E9F` on `Background #F8F9FA`** is ~2.7:1 contrast —
  **fails WCAG AA** for the dim secondary text used pervasively in hints,
  labels, and the (unreadable) inactive tabs. Worth darkening `Dim` in the Light
  variant.
- **Ayu Mirage `Dim #707A8C` on `Background #1F2430`** ≈ 3.4:1 — borderline.
- **No screen-reader / ARIA story** — inherent to ratatui/terminal; focus is
  conveyed only visually. Not actionable in this stack, but worth noting.
- **Unicode glyphs** (`▸▾▶‖✓✗⧗⊘💭⚙▌⠋`) assume a Unicode-capable font; on a
  legacy terminal they may render as `?`/boxes, breaking the status badges. No
  ASCII fallback.

### 3.4 Interaction edge cases

- **`o` vs `Ctrl+O`** — `o` opens the browser, `Ctrl+O` toggles verbose
  (`event.rs:1357-1361`). Easy to mistype; the modifier precedence is invisible.
- **`c` cancels a run, `Ctrl-C` quits** — adjacent and dangerous; only
  documented in the status-bar legend.
- **Hit-testing depends on the previous frame's geometry.**
  `translate_terminal_event` takes `&App` to read recorded bounds
  (`event.rs:1182`), so a click arriving before the first render (or after a
  resize before a redraw) could hit-test against stale/empty bounds. In practice
  the loop renders before processing input on startup and every event triggers a
  redraw before the next, so this is safe — but it's an implicit invariant worth
  a comment.
- **`CommandPaletteExecute` is handled in two places** — `resolve_io`
  (`event.rs:389-410`) extracts the action, and `App::update` (`app.rs:2552-2575`)
  also has a full handling path "for testing and direct calls". The dual path
  risks divergence (the comment acknowledges it).

## 6. Prioritized recommendations

Ranked by impact × leverage. Each is small unless noted.

### Immediate (doc + polish, no architecture change)

1. **Fix the README's "Limitations" + example args.** Remove the
   `session/request_permission` claim (it's implemented), remove `--yolo` from
   the example, document `WorktreePolicy` + the audit log, and update the
   persistence claim. **Highest-leverage single edit:** it corrects the
   project's self-presentation on its headline feature.
2. **Fix inactive tab styling** (`ui.rs:936-938`). One-line fix; eliminates the
   most visible polish defect.
3. **Seed `wall_clock_secs_config` from config** (`app.rs:1625`). Small fix;
   makes the countdown honest for non-default configs.
4. **Add a help/keymap overlay** (bind `?` or `h`). Medium effort; biggest
   discoverability win. Move Doctor to a palette entry or `!`.
5. **Make the error pane scrollable** (add `ScrollablePanel::ErrorPane`).
   Small-to-medium; the pane is the primary diagnostic surface.

### Short-term (UX completeness)

6. **`Theme::get` fallback instead of panic** (`theme.rs:48-53`). Robustness for
   future custom themes.
7. **Feedback on no-op overloaded keys** (`event.rs:1369-1396`). Emit a
   transient status message so `a`/`t`/`z` outside plan tabs aren't silent.
8. **Markdown render caching** keyed by `(text_hash, width)`. Perf fix for
   large plans/streaming responses.
9. **Resizable sidebar + min-size guard** (`ui.rs:90`). Small-terminal
   usability.
10. **Rename or implement the provider editor** (`event.rs:1300-1309`). Either
    "View Providers & Roles" or a real edit path.

### Medium-term (protocol hardening)

11. **Add a turn timeout in the ACP transport.** `send_request` should take a
    deadline; a wedged agent should produce a `Transport` error, not hang
    until the wall-clock cap. **Most significant protocol-level risk.**
12. **Wire `session/cancel`** into `AcpClient`/`AcpSession` so a long turn can
    be politely cancelled without killing the session. Enables pause-at-turn-
    boundary semantics.
13. **Thread `usage` and `stop_reason` through the trait boundary.** The TUI's
    per-role metrics and the orchestrator's refusal detection depend on these.
14. **Thread `run_id`/`task_id` into the audit context** (`transport.rs:503-504`)
    so audit entries correlate to runs/tasks.
15. **`WorktreePolicy` path validation.** Auto-allow should verify the
    tool-call's target paths actually reside under the worktree, not just key
    off the session cwd.

### Nice-to-have (code hygiene)

16. **Extract `drain_agent_turn`** shared helper for Developer/Reviewer
    (~130 lines deduped).
17. **Extract `combine_output`** shared helper (gate.rs + merge.rs).
18. **Make `run.json` atomic** (temp + rename) for consistency with
    `persist_graph`.
19. **Fix stale doc comments:** state_machine.rs counts (21/77/98 not
    19/65/84), run_metadata.rs worktree-path claim.
20. **Remove stale `#[allow(dead_code)]`** on used symbols
    (`is_plan_convention_dir`, `format_tasks_section`,
    `accordion_section_order`, `PlaceholderApi::empty`).
21. **De-duplicate `SettingsCommit` validation** between `App::update` and
    `event::commit_settings`.
22. **Resolve the forward-referenced stub events** (`RetryFocusedTask`,
    `DiscoverProject`) — either remove or wire them, don't leave dead stubs.

## 7. Closing judgment

Makina delivers what its VISION claims: a working orchestration spine, a
real-agent full loop, deterministic governance via gates, and a clean
TUI-over-api architecture. The `NoopBackend`-first strategy paid off — 872
hermetic tests pass without a model, and the real-agent run worked on the first
engine-level attempt. The two biggest gaps the trial findings flagged
(permission flow + task-graph persistence) are both closed. The concurrency
model is correctly reasoned about and I found no locking bugs. Worktree and
merge safety is the strongest part.

What's left is polish and protocol hardening, not rework. The README staleness
on permissions is the single highest-leverage fix (it undersells the project's
headline feature). The TUI has a cluster of small UX bugs — unreadable inactive
tabs, a hardcoded wall-clock countdown, no help screen, a non-scrollable error
pane, a read-only "editor" — that are each one-PR fixes and together would
take the UX from B to A. The ACP client needs a turn timeout and `session/cancel`
to be production-safe against wedged agents.

The foundation is solid. Build on it.
